# カリキュラム v3 レビュー → v3.1 修正案

## 問題点一覧

### P1: Unit末ポリシーとUnit実データの矛盾

**問題**: 設計思想4番で「Unit末は復習だけで終わらせない」と宣言しているが、Unit末パターンAとして「知識Unit（Unit 1, 4, 5, 6, 8）は復習だけ」と定義している。これは直接矛盾する。

さらに実データを見ると：
- Unit 4: reviewのみ（パターンA）と書いてあるが、`u4_game`（coached_game）が入っている
- Unit 5: reviewのみ（パターンA）と書いてあるが、`u5_game`（coached_game）が入っている
- Unit 6: reviewのみ（パターンA）と書いてあるが、`u6_game`（coached_game）が入っている
- Unit 8: reviewのみ（パターンA）と書いてあるが、`u8_game`（coached_game）が入っている

→ **パターンAに分類されたUnitの実データには全てcoached_gameが入っている。パターン分類が実態と一致していない。**

**修正方針**: パターンAを廃止。Unit 1以外は全てパターンB（review + game + reflection）に統一。Unit 1のみreviewだけ（まだ対局に必要な駒が揃っていないため）。

---

### P2: reflectionノードの「全レッスンに操作」原則との衝突

**問題**: 設計思想2番で「全レッスンに操作と判断がある」と宣言しているが、`reflection`は3カードを読むだけで操作がない。

**修正方針**: reflectionは独立ノードではなく、coached_gameノードの**終了フェーズ**として扱う。ロードマップ上のノード数には数えない。ユーザーから見ると「ガイド対局」の一部。

---

### P3: Unit 1のCan-doと中身のズレ

**問題**: Can-doに「王手を防ぐ方法を1つ以上実行できる」とあるが、Unit 1のレッスンに受けの操作はない。受けはUnit 5のテーマ。

**修正方針**: Unit 1のCan-doから「王手を防ぐ方法を1つ以上実行できる」を削除。Unit 1は「王手をかける」までに留める。

---

### P4: 初期診断でUnit 1〜4スキップの危険性

**問題**: 90秒診断でUnit 4まで飛ばせるとしているが：
- Unit 3（持ち駒・成り）を飛ばすとcoached_game以降で混乱する
- 飛ばしたUnitの復習問題が出せない（未学習なので）
- 「少し指せる」人でも成りや持ち駒の操作UIは初見

**修正方針**: スキップ先をUnit 1 or Unit 4の2択に限定する。
- 「まったく初めて」→ Unit 1から
- 「ルール知ってる / 少し指せる」→ Unit 4から（ただしUnit 1〜3はロードマップ上で完了済みマーク。いつでも戻れる）

---

### P5: Unit 7の情報量

**問題**: Unit 7に矢倉・美濃・舟囲い・穴熊の4つの囲い + 崩し方 + 急戦vs持久戦が詰め込まれている。初心者にとって情報量が多い。

**修正方針**: Unit 7は矢倉・美濃の2つに絞る。舟囲い・穴熊は拡張ポイント（Unit 10+）に移す。崩し方は1パターンのみ残す。

**Before**: 9レッスン（囲い4種 + 崩し + 比較 + review + game）
**After**: 7レッスン（囲い2種 + 崩し1 + 比較 + review + game）

---

### P6: ロードマップノードの分類が不明確

**問題**: `learn`, `guided_move`, `find_move`, `compare`は全てレッスンノードだが、ロードマップ上でどう区別するのか不明。Duolingo Chessでは各種別にアイコンがある。

また、`coached_game`と`reflection`がロードマップ上の独立ノードなのか、1つのノードなのか不明確。

**修正方針**: ロードマップノードを3種類に整理する。

| ノード種 | ロードマップアイコン | 内容 |
|---|---|---|
| `lesson` | 📖 | learn / guided_move / find_move / compare のいずれか。内部のステップ構成で区別。ロードマップ上は統一アイコン |
| `review` | 🎯 | 復習テスト |
| `battle` | ⚔️ | coached_game + reflection をセットで1ノード |

→ ユーザーに見せるのはこの3種のみ。lesson_typeはレッスンデータ内部の属性。

---

### P7: 「82レッスン」の数え方

**問題**: reflectionを独立カウントすると82だが、ユーザーに「82レッスン」と見せるとreflection（読むだけ）が含まれて体感と合わない。

**修正方針**: P2の修正に従い、reflectionはbattleノードの一部。ユーザーに見せるノード数を再計算する。

---

## ノード分類（Node Taxonomy）v3.1

### ロードマップノード（ユーザーに見えるもの）

| 種別 | コード | アイコン | 説明 | 画面 |
|---|---|---|---|---|
| レッスン | `lesson` | 📖 | 5〜7ステップのインタラクティブな学習。全テキストはコーチ吹き出し。駒タップで拡大。正解で駒移動。正解後フッタースライドイン | NativeLessonScreen |
| 復習 | `review` | 🎯 | 過去のミス＋弱点問題の混合出題。5〜10問 | NativeLessonScreen（review用プール） |
| 実戦 | `battle` | ⚔️ | coached_game → reflection を1ノードとして実行。対局後に3カード表示 | CoachedGameScreen（新規） |

### レッスン内部のステップ種別（内部属性、ユーザーには見せない）

| コード | 操作 | 用途 |
|---|---|---|
| `move` | 駒を選択→移動先をタップ | ガイド付き/自力の駒移動 |
| `tap_square` | マスをタップ | 利きの確認、駒の発見 |
| `quiz` | 選択肢をタップ | 知識確認 |
| `compare` | 候補選択肢をタップ + why_text表示 | 比較判断（Why step） |

### レッスンの内部分類タグ（lesson_type、メタデータ用）

| タグ | 意味 | 使い方 |
|---|---|---|
| `learn` | 概念導入。ガイド多め | ステップにguided系が多い |
| `guided_move` | ガイド付き操作中心 | ステップにmove(guided=true)が多い |
| `find_move` | 自力発見中心 | ステップにmove(guided=false)が多い |
| `compare` | 比較判断中心 | compareステップがメイン |

→ これはロードマップ表示には使わない。データ分析・復習ロジック用。

## レッスンのレイアウト仕様（実装確定事項）

今日作ったbasics_pawnレッスンに準拠。全レッスン共通：

| 項目 | 仕様 |
|---|---|
| テキスト表示 | 全てコーチ（おじいちゃん）の吹き出しから。画面上に独立テキストは置かない |

| ライフ | ♥5つ表示。0で失敗→再挑戦 |
| プログレスバー | 画面上部に常時表示 |
| コーチキャラ | 左上にRiveアニメーション（おじいちゃん）。絵文字フォールバック |
| 盤面 | 9x9。木目色。タッチは`onPressIn`で即反応 |
